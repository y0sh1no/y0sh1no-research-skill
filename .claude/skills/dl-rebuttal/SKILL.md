# 评审回应、改投与定稿

先读取[运行环境](references/library/packaging/runtime/portable.md)。基于实际意见、稿件和已有证据，按用户当前任务选择回应、改投或定稿。

## 回应方法

1. 核对会议/期刊、轮次、字数/字符数、单文档或逐 reviewer 形式及实际提交规则。拆出每条关注的问题和已有支持位置。
2. 按正确性、创新性、实验证据、公平比较、意义和清晰度等分类，找跨 reviewer 的共同核心。优先解决影响结论的实质问题。
3. 每项先直接回答，再给具体证据，最后说明对稿件的含义。承认成立的局部问题，同时准确解释仍成立的贡献。
4. 对“等同于已有方法”比较机制、假设和实际结果；对实验要求列已有/新增/尚未执行状态。没有证据时收窄回答，不编造数字、预注册或承诺。
5. 检查回应是否覆盖原问题、数字/位置与当前版本一致、字数符合要求、承诺与实际修改对应。写成可直接使用的回应稿。

采用[证据参考](references/library/shared/evidence.md)。措辞尊重且明确，不推测 reviewer 动机，不以修辞代替证据。没有用户授权或已完成的变更不写成已承诺交付。

## 改投与定稿

改投时结合原意见与新受众调整贡献表达、格式和证据缺口；直接使用当前目标的官方模板和要求。定稿时检查版本、匿名/作者信息、引用、图表、附录与发布产物的一致性。发表、提交或公开仓库操作遵循用户实际授权。

## 可选协作

可按问题组起草，再由证据/评审视角核查回答是否命中关注点；共享共同设定，逐线程回复保持自足。只核查重要分歧，不持续评分。见[协作方法](references/library/shared/collaboration.md)。

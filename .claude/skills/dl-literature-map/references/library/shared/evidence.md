# 证据与主张

用于文献综合、实验解释、论文和审阅中的重要判断。简单讨论直接在答案中表达，只有需要交接或追溯时才建立表格。

## 最小关系

| 对象 | 有用信息 |
|---|---|
| 问题 | 要解释或改善什么，在哪种条件下 |
| 证据 | 原文页/节/图表，或结果文件字段；方法、数据、指标和比较条件 |
| 主张 | 证据实际支持的命题，量词和适用范围 |
| 未解决项 | 缺失材料、竞争解释、相反结果，以及影响哪个判断 |

分别核查来源存在、引用数值一致、实验比较有效、结论得到支持。前一项通过不能代替后一项。例如结果文件包含 83.1，不说明相较基线有显著提升，也不说明改善来自目标模块。

## 几类状态

- **观察**：某个数据、运行或论文报告了现象；注明条件。
- **解释假说**：可能产生现象的机制，附能区分它的预测。
- **支持**：在已检查条件下，证据增加了该解释或主张的可信度。
- **矛盾**：有效且相关的证据与命题冲突；检查比较条件后再判断。
- **尚未核验**：访问不足、数值解析失败、缺文件或未运行。描述具体原因。

“没找到证据”“证据不足”“反例已出现”分别表达。一次失败运行也可能来自实现或环境，不能直接否定科研假说。负结果保存条件和检测能力；差异不显著不等于证明等效。

材料访问深度（摘要、正文、附录、代码、原始结果）与研究质量分别判断。摘要可以支持它明确报告的有限事实，方法有效性和机制判断通常需要更多材料；全文可读也不自动保证结论可靠。

## 追溯到实验

对进入稿件的重要数值，能回到：图表单元 → 原始结果字段 → 分析脚本及聚合规则 → 运行配置、代码版本、数据划分、checkpoint。复用已有日志和文件；无需为普通任务建立数据库或统一 ID 系统。

区分用户决定、作者主张、AI 推断和实际执行。正文采用范围匹配的措辞；不能通过润色把相关性变成因果、局部结果变成普遍结论。

# 训练配置与故障定位

适用：当前深度学习项目的训练、复现、调试和成本比较。本文为跨任务方法参考，具体 API 按项目安装版本查官方资料；未在本库运行 GPU 训练。

## 会改变结果含义的配置

记录训练样本/有效 token、优化更新数、每设备 batch、并行进程、累积步数、loss 归约、学习率日程、精度与 checkpoint 选择。常见等长样本 DDP 下，有效样本 batch 约为每设备 batch × 进程数 × 累积步数；变长 token、尾批、采样/打包和非 DDP 并行需要按实际有效单位计算。

区分 micro-step、optimizer update、epoch 和有效 token 数。loss 日志的最后一个 micro-batch 不等于整个更新的平均值。变长序列的 token loss 需要按有效 token 数加权；梯度累积的缩放若由框架管理，额外除一次会改变梯度。[Accelerate 累积指南](https://huggingface.co/docs/accelerate/en/usage_guides/gradient_accumulation)

## 实际定位顺序

| 现象 | 优先检查 |
|---|---|
| loss 不下降 | 标签/掩码、训练参数是否在 optimizer、梯度路径、学习率、是否意外 eval/freeze |
| NaN/Inf/尖峰 | 首个非有限量、样本与长度、归一化分母、数值范围、精度、梯度与优化器状态 |
| OOM | 出错阶段、实际序列/图像尺寸、激活/参数/优化器、意外保存计算图、评估累积 |
| 多卡指标异常 | 分布式采样重复、样本/分母聚合、尾批、局部均值的权重 |
| 恢复后漂移 | 模型、优化器、调度器、随机状态、数据位置、累计更新数是否一致 |

根据症状定位真实原因；先用小量真实数据验证关键路径，再进行当前范围的正式运行。不要把换设备、降精度或过滤困难样本当作无影响修复。

## 可重复性与记录

固定 seed 只控制相关随机源；版本、设备、数据加载与不同计算内核仍可能影响结果。需要精确复现时核查当前框架的确定性设置及性能成本，避免声称跨环境位级一致。

保存有效配置、代码版本、数据版本/划分、命令、状态与原始结果。用户当前项目已有记录工具就沿用，无需强制引入实验追踪服务。
